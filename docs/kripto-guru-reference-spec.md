| Источник | Что проверено | Ограничение |

| Предыдущий QA-комментарий LEAD `6948242041` | Зафиксированы P0 проблемы после предыдущего артефакта `14328209514` | Для актуального состояния приоритет отдаётся более свежему артефакту `14328718079` |

**Важно о масштабе:** имена артефактов обозначают CSS viewport. PNG для 390×844 имеет растр 1170×2532, а для 430×932 — 1290×2796 (3×). Не сравнивать PNG-пиксели напрямую с CSS-пикселями без деления на 3.

Визуальная цель из инструкций LEAD: максимально точная копия предоставленного эталона; единственная разрешённая брендовая замена — название/wordmark на **Kripto Guru**. Не вводить самостоятельный дизайн-язык. Русский UI, DEMO-only, LIVE locked.

## 6. Scroll, fixed, safe-area и клавиатура: текущая реализация PR #25

Это описание текущего CSS, а не подтверждённые параметры эталона:

- `#kg-main` — обычный основной scroll-контейнер с нижним padding; в конце stylesheet задано `176px + safe-area`.
- `#kg-nav` — fixed bottom navigation, left/right 10px, bottom 8px + `env(safe-area-inset-bottom)`.
- `.kg-subscreen` — fixed на весь viewport, собственный vertical scroll, `overscroll-behavior: contain`, верхний padding включает safe-area.
- Asset actions — отдельный fixed bottom dock; его высота должна учитываться в нижнем scroll clearance.
- Ticket — отдельный fixed subscreen; кнопка проверки и нижняя группа имеют отдельные CSS правила. В итоговом capture остаётся визуально избыточный пустой участок, значит текущая раскладка не достигает требуемой композиции.
- Modals — fixed bottom-aligned cards с затемнённым backdrop.
- В артефакте нет кадров открытой клавиатуры. Реальное изменение visual viewport при открытии клавиатуры, удержание фокуса, прокрутка к полю и возврат после закрытия **не проверены**.
- Safe-area CSS не заменяет проверку на реальном Telegram iOS WebView.
