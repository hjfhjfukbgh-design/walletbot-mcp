# Центральный оркестратор Kripto Guru — MVP

## Что делает эта версия

Workflow `.github/workflows/kripto-guru-orchestrator.yml`:
- запускается вручную или по расписанию раз в 2 часа;
- ищет одну открытую GitHub Issue с меткой `agent-ready`;
- обрабатывает не более одной задачи за запуск;
- вызывает Gemini с fallback-моделью, чтобы назначить одну из ролей ARCHITECT / FRONTEND / BACKEND / QA / SECURITY / ANALYST;
- проверяет полноту постановки и формирует пакет исполнителю;
- публикует пакет в отдельной ветке и Draft PR;
- оставляет ссылку в Issue и меняет метку на `agent-dispatched`.

Ограничитель частоты: максимум одна Issue за запуск; расписание — 12 запусков в сутки. При пустой очереди LLM не вызывается. На ошибках временного характера допускается ограниченный retry и fallback на вторую модель.

## Что эта версия НЕ делает

- Не пишет и не изменяет прикладной код.
- Не запускает отдельные workflow агентов автоматически.
- Не исправляет замечания и не повторяет QA-цикл.
- Не сливает PR, не деплоит и не включает LIVE.
- GitHub Actions остаётся событийным исполнителем, а не постоянно работающим сервером.

Это первый центральный узел очереди, а не завершённая автономная команда.

## Как поставить задачу

Создать GitHub Issue и добавить метку `agent-ready`. В описании обязательно указать:
1. Цель и причину.
2. Контекст и связанные файлы/PR.
3. Разрешённую область изменений.
4. Что запрещено менять.
5. Проверяемые критерии приёмки.
6. Команды проверок и требуемые доказательства.

Если данных недостаточно, диспетчер должен пометить пакет BLOCKED, а не придумывать требования. Workflow автоматически создаёт метки `agent-ready` и `agent-dispatched`; секрет `GEMINI_API_KEY` должен быть доступен GitHub Actions.

## Безопасность

- Никаких платных API или подписок.
- Секреты только в GitHub Actions Secrets.
- Все результаты — отдельные ветки и Draft PR.
- Человеческое утверждение обязательно.
- Реальные сделки, LIVE, production deploy и merge запрещены.
