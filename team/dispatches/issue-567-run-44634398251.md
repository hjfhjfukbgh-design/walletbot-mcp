Добавить tenant-scoped атомарное хранение открытых позиций AI PAPER с использованием decision ledger из задачи #563 во внутреннем Durable Object хранилище.

Разрешённая область изменений:
- Файлы `src/trading/engine.ts` и `test/trading-engine.miniflare.test.ts` (не более 3 файлов, не более 250 измененных строк).

Запрещённые действия:
- Никаких публичных HTTP-маршрутов или UI (только внутренний контракт DO).
- Никаких вызовов Walt, реальных ордеров, переводов, секретов, LIVE или деплоя (AI Trading остаётся paper-only).
- Никаких новых зависимостей.
- Не модифицировать DEMO accounts или DEMO ledger.

Пошаговый план исполнителя:
1. Создать ветку для задачи #567.
2. Реализовать валидацию входящих параметров в `src/trading/engine.ts`.
3. Добавить проверку decision row (`risk_pass=1`, соответствие `side` и `signal`).
4. Реализовать резервирование средств с использованием `BigInt` / integer micro-units.
5. Реализовать транзакцию (`transactionSync`) для проверки идемпотентности, ограничения одной позиции на user+symbol, баланса, вставки строки позиции, обновления баланса и добавления записи в ledger.
6. Реализовать GET-метод с фильтрацией по `user_id`.
7. Добавить минифлар-тесты в `test/trading-engine.miniflare.test.ts` для покрытия всех сценариев (идемпотентность, проверка баланса, отклонение невалидных решений, изоляция тенантов).

Критерии приёмки:
- Успешно проходят тесты: фондирование двух пользователей, запись одобренных решений, независимое открытие позиций.
- Повторный вызов с тем же ключом идемпотентности возвращает сохраненную позицию без повторного списания; для разных пользователей ключи независимы.
- Иностранные/отклоненные/hold решения не могут открыть позицию.
- Недостаток баланса, невалидные входные данные или дубликат открытия по тому же символу не меняют баланс, ledger и позиции.
- GET-запросы возвращают исключительно строки текущего вызывающего пользователя.
- Все существующие и новые тесты успешно выполняются через `npm test`.

Обязательные проверки и доказательства:
- Выполнение `npm test` с подтверждением успешного прохождения тестов в miniflare.
- Проверка ограничений на измененные файлы и объем кода (<= 3 файлов, <= 250 строк).

Риски/неизвестное:
- Возможные гонки (race conditions) при одновременных запросах — требуют строгого использования транзакций `transactionSync` внутри Durable Object.
