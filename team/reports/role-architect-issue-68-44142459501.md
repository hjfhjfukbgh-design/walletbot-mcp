### Доказательства (файлы и символы)
1. **Точка входа и маршрутизация API**:
   - `src/api.ts`: Обрабатывает маршруты `/api/*`, проверяет заголовок `X-Api-Key` или валидирует `initData` Telegram Mini App (`validateTelegramInitData`), изолирует пользовательское окружение через `tenantEnv` (`src/tenants.ts`).
   - `src/index.ts`: Содержит Cloudflare Worker `fetch`, обработку webhook Telegram (`/telegram`), OAuth callback (`/oauth/callback`), страницу настройки (`/setup`) и плановый запуск `scheduled` через `handleTenantTick`.
2. **Торговые режимы и защита**:
   - `src/bot.ts`: Содержит функцию `tick()`. Наличие флага `live` явно блокирует выполнение:
     ```ts
     const live = state.mode === "live";
     if (live) {
       state.running = false;
       state.paused = "LIVE временно заблокирован до включения подтверждения каждой сделки и проверки лимитов риска";
       msgs.push(`⏸️ ${state.paused}`);
       return;
     }
     ```
   - `src/service.ts`: В функции `setMode()` при переходе в `live` возвращает ограничение:
     ```ts
     if (target === "live") {
       return "LIVE пока закрыт: сначала подключаем подтверждение каждой сделки, сверку открытых позиций и жёсткие лимиты риска. ДЕМО работает полностью без кошелька.";
     }
     ```
   - `src/trading/engine.ts`: Реализует изолированный `TradingEngine` на базе Durable Objects для DEMO-сделок, расчёта PnL и соблюдения лимитов риска по котировкам Hyperliquid.

### Риски и пробелы
- **Аутентификация Mini App**: Безопасность взаимодействия Mini App с Worker опирается на валидацию `initData` (`validateTelegramInitData`) или заголовок `X-Api-Key`. Ошибки в цепочке `tenantEnv` могут привести к утечке контекста пользователя при неверной изоляции KV.
- **Состояние синхронизации**: Разделение логики между Cloudflare Worker (cron/cron triggers каждые 5 минут) и Telegram Serverless Mini App требует строгой консистентности KV-хранилища (`BotState` и изолированных `tenant:` ключей).
- **Ограничения платформы**: Лимиты Cloudflare KV (до 1000 записей на бесплатном тарифе в день) требуют минимизации операций записи (запись состояния один раз за tick и фиксация сделок только по событиям).
