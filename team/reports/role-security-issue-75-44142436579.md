### Доказательства и точные пути (Evidence & Code Paths)

1.  **Авторизация и верификация Mini App (`src/api.ts`):**
    *   *Путь:* `src/api.ts` (строки 27-37)
    *   *Фрагмент:* `const authorization = req.headers.get("Authorization") ?? ""; if (authorization.startsWith("tma ")) { telegramUserId = (await validateTelegramInitData(authorization.slice(4), env.TELEGRAM_BOT_TOKEN)) ?? ""; }`
    *   *Проблема:* Функция `validateTelegramInitData` не определена в данном файле или импортируемых модулях видимой кодовой базы, что может приводить к ошибкам выполнения или небезопасному обходу валидации при отсутствии импорта.
2.  **Изоляция арендаторов (Tenant Isolation - `src/tenants.ts`):**
    *   *Путь:* `src/tenants.ts` (строки 13-44)
    *   *Фрагмент:* Переопределение `KVNamespace` через префиксы `tenant:${userId}:`.
    *   *Проблема:* Глобальные ключи, такие как `oauth:client`, исключаются из префикса (`key === "oauth:client" ? key : prefix + key`), что создает общий кэш OAuth-клиента для всех пользователей, потенциально нарушая строгую изоляцию мульти-арендаторности (multi-tenant isolation).
3.  **Защита LIVE-режима (`src/bot.ts`):**
    *   *Путь:* `src/bot.ts` (строки 50-55)
    *   *Фрагмент:* 
        ```typescript
        if (live) {
          state.running = false;
          state.paused = "LIVE временно заблокирован до включения подтверждения каждой сделки и проверки лимитов риска";
          msgs.push(`⏸️ ${state.paused}`);
          return;
        }
        ```
    *   *Статус:* Защита жестко вшита в тикер бота. Реальные ордера через этот путь отправлены быть не могут.

### Риски и пробелы (Risks & Gaps)

*   **Пробелы в валидации Telegram Data:** Отсутствие явной реализации `validateTelegramInitData` в предоставленном контексте создает риск неавторизованного доступа к API эндпоинтам `/api/*`.
*   **Состояние гонки (Race Conditions) в KV:** Использование Cloudflare KV для хранения изменяемого состояния бота (`bot:state`) без распределенных блокировок (Locks) может приводить к потере данных при параллельных вызовах Cron-триггеров и Telegram Webhook.
*   **Угрозы безопасности секретов:** Токены и секреты (`API_SECRET`, `TELEGRAM_BOT_TOKEN`) передаются через переменные окружения и `wrangler.toml`, требующие строгого контроля доступа на уровне CI/CD GitHub Actions.

### Критерии приёмки (Acceptance Criteria)

1.  Эндпоинты `/api/*` возвращают HTTP 401 Unauthorized при отсутствии или неверной подписи `Authorization: tma ...` или заголовка `X-Api-Key`.
2.  Изоляция арендаторов (`tenantEnv`) полностью разделяет учетные данные и историю сделок без утечки глобального состояния.
3.  LIVE-режим остается заблокированным на уровне кода (`src/bot.ts`), исключая отправку ордеров на реальные биржи.
4.  Все изменения проходят статический анализ типов (`npm run typecheck`).
