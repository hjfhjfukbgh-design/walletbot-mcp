## Доказательства уязвимостей (с точными путями и символами)

1. **Критическая уязвимость Auth Bypass / Tenant Isolation (`src/api.ts`)**:
   * В функции `handleApi` проверка токена Telegram Mini App (`validateTelegramInitData`) упоминается в комментариях и логике, но сама функция **не определена** в файле. 
   * Если `authorization` заголовок отсутствует или не содержит префикс `tma `, переменная `telegramUserId` остается пустой (`""`).
   * Строка: `if (!/^\d{1,20}$/.test(telegramUserId)) return fail("Требуется открыть приложение через Telegram.", 401);` **не срабатывает** для незалогиненных/анонимных запросов к эндпоинтам `GET demo`, `POST demo/open`, `POST demo/close`, так как код прерывается или проваливается в ветку без валидации (см. обрыв файла на `leverage = N` в `src/api.ts`).

2. **Обрыв исходного кода (Syntax/Logic Break) (`src/api.ts` и `src/manual.ts`)**:
   * Файл `src/api.ts` обрывается на строке с неполным выражением `const leverage = N`. Это приводит к нарушению сборки TypeScript (`tsc --noEmit`), падению Worker на этапе развертывания и невозможности корректной работы API.
   * Файл `src/manual.ts` обрывается на `await saveState(` в функции `closeManualTrade`, что делает модуль ручной торговли синтаксически невалидным.

3. **Отсутствие проверки прав владельца в Telegram Webhook (`src/tenants.ts`)**:
   * Функция `handleTenantUpdate` принимает обновления от любых пользователей Telegram, которые смогли отправить сообщение боту:
     ```ts
     const userId = String(msg.from.id);
     if (String(msg.chat.id) !== userId) return;
     ```
   * Любой пользователь может инициализировать свой собственный `tenantEnv` и запустить торговые циклы, исчерпывая ресурсы KV и Durable Objects.

4. **Риск-лимиты и манипуляции с вводом (`src/trading/engine.ts` / `src/api.ts`)**:
   * Демо-движок (`TradingEngine`) использует фиксированный сид `DEMO_SEED = 1_000n * MONEY_SCALE`, но не проверяет должным образом привязку `userId` к строгим криптографическим сессиям, доверяя параметрам, передаваемым из тела HTTP-запросов (`POST demo/open`).

## Риски и пробелы
* **Целостность данных**: Незавершенные функции из-за обрыва кода (`src/api.ts`, `src/manual.ts`) вызывают фатальные ошибки выполнения (`ReferenceError` / `SyntaxError`).
* **Аутентификация**: Отсутствие реализации `validateTelegramInitData` позволяет злоумышленнику подделывать заголовки `Authorization: tma ...` или обращаться к незащищенным маршрутам.
* **Финансовые риски (DEMO)**: Отсутствие жестких лимитов на стороне бэкенда для демо-ордеров открывает вектор для манипуляций с виртуальным балансом.
