### 1. Архитектурный вердикт
Проект `walletbot-mcp` представляет собой serverless-приложение на **Cloudflare Workers** (TypeScript), управляющее гибридной торговой логикой (симуляция DEMO + интеграция с Walt MCP) через Telegram Bot API и Telegram Mini App (`tgcloud`). 

*   **Сильные стороны:** Использование Cloudflare KV для изоляции пользовательских данных (`src/tenants.ts`), строгая двухэтапная схема MCP (`perps_prepare_*` → `perps_execute_operation` с подтверждением в `src/walt.ts`), безъядерная арифметика с фиксированной точкой для демо-движка (`src/trading/money.ts`), а также чётко разграниченные риски и жесткий запрет LIVE-торговли на уровне кода (`src/service.ts`, `src/risk.ts`).
*   **Главные уязвимости и риски:**
    1.  *Отсутствие единой очереди задач (Task Queue) в коде Worker:* текущие Cron-триллеры (`*/5 * * * *`) и API-запросы обрабатывают тики параллельно, потенциально создавая состояние гонки при обновлении позиций или записи в KV.
    2.  *Связанность внешнего API Mini App и логики Worker:* прямые вызовы к эндпоинтам требуют строгой валидации через `X-Api-Key` или `initData`.
    3.  *Ограничения GitHub Actions / Лимиты Gemini:* отсутствие нативных детерминированных очередей для фоновых задач вне Cloudflare Durable Objects.

### 2. Схема компонентов и поток задачи

```
[ Telegram User ] ──( message )──▶ [ Telegram API / Webhook ] ──▶ [ Cloudflare Worker /telegram ]
                                                                        │
[ Mini App UI ] ────( fetch/POST )───▶ [ Cloudflare Worker /api/* ] ──( Isolate Tenant )
                                                                        │
[ Cron */5m ] ──────────────────────▶ [ Cloudflare Worker scheduled ] ──▼
                                        [ Trading Engine (Durable Objects / KV) ]
                                                        │
                                                        ▼
                                       [ Walt MCP / Hyperliquid Public API ]
```

**Поток критической задачи (например, открытие ордера / тика сетки):**
1. Входящий триггер (`scheduled` Cron или API POST) извлекает список арендаторов через `listTenantIds(env)`.
2. Для каждого арендатора инициализируется изолированное окружение через `tenantEnv(env, userId)`.
3. Движок запрашивает актуальную котировку, проверяет риски (`src/risk.ts`), формирует операцию через MCP/Engine и сохраняет состояние в KV / SQLite (Durable Objects).
4. Результат журналируется; при сбое или срабатывании лимитов отправляется уведомление в Telegram-чат владельца.

### 4. Текущие подтверждённые возможности и пробелы

#### Подтверждённая функциональность:
*   Сборка и типизация TypeScript (`npm run typecheck` настроен в `package.json`).
*   Модульные тесты через Vitest (`npm test`).
*   Изоляция данных пользователей по префиксам в KV (`src/tenants.ts`).
*   Двухэтапная безопасность вызовов Walt MCP (`src/walt.ts`).
*   Жёсткое разделение DEMO-режима (симуляция) и LIVE-заглушки.

#### Пробелы (Gaps):
*   Отсутствие единой персистентной очереди задач (Task Queue) для асинхронных операций с защитой от дублирования при параллельных тиках.
*   Отсутствие автоматического мониторинга падений WebSocket/сокета в хэндлерах (частично покрыто watchdog в `TradingEngine`).
*   Зависимость от внешних публичных API котировок (Hyperliquid) при недоступности основных эндпоинтов.

### 5. Риски и меры

1.  **Риск:** Состояние гонки при одновременном запуске Cron-тика и ручного вызова API `/api/grid` или `/api/manual`.
    *   *Мера:* Использование транзакций SQLite в Durable Objects (`TradingEngine`) и атомарных операций записи в KV.
    2.  **Риск:** Утечка секретов через логи или окружение Mini App.
    *   *Мера:* Секреты передаются только через `wrangler secret` или GitHub Actions Secrets; Mini App авторизуется строго по `initData` и серверному `API_SECRET`.
    3.  **Риск:** Превышение лимитов бесплатных ресурсов Cloudflare (KV writes, Cron triggers).
    *   *Мера:* Оптимизация частоты записи в KV (не чаще 1 раза за тик на пользователя) и удержание cron в рамках лимита Free Tier (до 5 триггеров).
