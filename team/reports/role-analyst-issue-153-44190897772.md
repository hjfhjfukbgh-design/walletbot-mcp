## Цель
Провести фактологический аудит качества рыночных данных Kripto Guru и дать конкретную спецификацию точного и устойчивого data layer для LIVE и DEMO.

## Подтверждённые точки
- `src/prices.ts`: publicMid/publicContracts получают Hyperliquid allMids и metaAndAssetCtxs.
- `src/walt.ts`: Walt.rate() использует perps_latest_rate; комментарий описывает цену закрытия 1m.
- `src/api.ts`: GET price и GET chart обслуживают Mini App.
- `miniapp/web/kripto-guru-api.js`: клиент нормализует рынки, цены и candles.
- PR #147 содержит новый SVG renderer, но остаётся Draft.

## Исследовать и представить отчёт
1. Проследить фактический путь данных для каждого режима: LIVE quote, DEMO quote, chart OHLC, market list, positions mark price.
2. Выявить расхождения источников/инструментов: Walt vs Hyperliquid, spot/perp, USD/USDC, mark/mid/last/close, timestamp/timezone.
3. Определить как обнаруживать stale quotes, missing candles, rate limits, timeouts и частичные отказы; никаких fallback на выдуманную цену/ноль.
4. Сравнить реально доступные бесплатные/текущие способы обновления (polling vs WebSocket) и стоимость/лимиты; не предлагать подключение платного провайдера без оценки.
5. Сформировать единый data contract: source, instrument, quoteType, price, timestamp, ageMs, precision/tickSize, status.
6. Дать короткий план внедрения по отдельным code issues с файлами и тестами, отдельно для LIVE и DEMO.
